# SmartKóz

Приложение для учёта смен, наблюдения за сотрудниками и обеспечения производственной безопасности. Node.js + SQLite, локальные модели YOLO и помощник через Groq.

## Запуск на Windows

Установите [Node.js 24 LTS](https://nodejs.org/), [Python 3.12 x64](https://www.python.org/downloads/) и Chrome или Edge. При установке Python оставьте включённым Python Launcher.

Откройте PowerShell:

```powershell
git clone https://github.com/krzhq/SmartKoz_amygdala.git
cd SmartKoz_amygdala
npm ci
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
```

В `.env` укажите свой ключ, если нужен помощник:

```dotenv
PORT=3000
GROQ_API_KEY=ваш_ключ
GROQ_MODEL=openai/gpt-oss-20b
```

Затем:

```powershell
npm start
```

Откройте **http://localhost:3000**. Не закрывайте терминал с сервером. Остановка — **Ctrl+C**.

В следующий раз достаточно `npm start`. Активировать `.venv` отдельно не нужно: сервер находит её сам. Зависимости переустанавливайте после изменения `package-lock.json` или `requirements.txt`.

## Вход

При первом запуске создаётся руководитель: **rukovod@gmail.com**, пароль **admin**. Это начальный доступ для локальной демонстрации. Пароль меняется по нажатию на имя аккаунта.

Сотрудник регистрируется через «Новый сотрудник? Зарегистрироваться» на странице входа. Для одновременной работы двух ролей используйте обычное окно браузера и инкогнито либо два разных браузера. Смена начинается одной кнопкой, без проверки формы и фотографии.

Другого первого руководителя можно задать через `ADMIN_EMAIL` и `ADMIN_PASSWORD` в `.env`. Они применяются к пустой базе при первом запуске.

## Данные

В репозитории находится чистая стартовая база `data/smartkoz.db`: без сотрудников, сессий, переписки и истории. Аккаунт руководителя создаётся при запуске. Если файла базы нет, приложение создаст его само.

Новые данные сохраняются после перезапуска. Все устройства должны подключаться к одному серверу: открытые страницы получают изменения через SSE. Копировать базу между браузерами не нужно.

Загрузки находятся в `data/uploads`, резервные копии — в `data/backups`. Эти папки, `.venv`, `node_modules` и `.env` исключены из Git. Рабочую базу с пользовательскими данными не публикуйте вместо стартовой.

## Что доступно

- **AI-мониторинг:** три исходных видео — СИЗ, падения и сонливость. Рамки YOLO сохранены рядом с записями; при отсутствии результатов запускается анализ.
- **Транспорт:** две записи КПП. Через 3 секунды видимости номера сохраняется въезд и открывается журнал с номерной плашкой, датой и временем.
- **Каска:** камера ноутбука, телефона или Iriun. Разрешите доступ в браузере и выберите источник. До начала смены доступна проверка камеры, на смене предупреждения сохраняются за сотрудником. Первый запуск модели занимает несколько секунд.
- **Помощник:** закладка справа. Без ключа Groq остальные функции работают.
- **Экстренные ситуации:** сотрудники на смене получают оповещение и подтверждают безопасность; руководитель видит статусы.

Имя «Иван Иванов Иванович» в записях транспорта и сонливости задано для демонстрации. Распознавания личности по изображению нет.

## Модели

Все веса и видео включены в репозиторий. CUDA и отдельная видеокарта не требуются: зависимости настроены для CPU.

| Файл | Назначение |
| --- | --- |
| `outfit/outfitcheck.pt` | СИЗ |
| `fall/falling.pt` | Падения |
| `microdream/dreameye.pt` | Глаза и сонливость, включая каску |
| `FORTRANSPORT/carsnumber.pt` | Номерные знаки |

Текст номера читается Windows OCR. Результаты для двух комплектных видео уже сохранены в `public/assets/vision`. Произвольный живой поток КПП автоматически не подключается.

## Другие устройства

Для просмотра в одной сети откройте `http://IP_КОМПЬЮТЕРА:3000`. IPv4 можно посмотреть через `ipconfig`. Разрешите Node.js доступ в частной сети, если Windows спросит.

Камере браузера нужен `localhost` или HTTPS. Для камеры телефона по Wi-Fi настройте сертификат, которому телефон доверяет: [инструкция](SMART_HELMET.md). Пути задаются через `TLS_CERT_FILE` и `TLS_KEY_FILE`.

## Если возникла ошибка

- **Не найден Python:** проверьте `py -3.12 --version` и наличие `.venv`. Свой путь к интерпретатору можно указать через `PYTHON` в `.env`.
- **Нет Python-модуля:** повторите установку через `.\.venv\Scripts\python.exe -m pip install -r requirements.txt`.
- **Ошибка Node-зависимости:** используйте Node.js 24 LTS и повторите `npm ci`.
- **Порт занят:** остановите предыдущий сервер или измените `PORT` в `.env`.
- **Помощник недоступен:** проверьте ключ в `.env` и доступ к Groq. Новый ключ подхватывается со следующего запроса.
- **Камера не открывается:** разрешите доступ в браузере и закройте программы, занявшие камеру. Для Iriun нужен её запущенный клиент.
- **Изменения не появились:** для страницы нажмите Ctrl+F5. После изменения серверного кода остановите старый процесс и снова выполните `npm start`.


## Vercel

В `package.json` указана версия Node.js `24.x`. В Vercel выберите **Settings → Build and Deployment → Node.js Version → 24.x**, затем запустите Redeploy. Настройка `engines.node` имеет приоритет над версией в панели Vercel; сообщение об override само по себе может быть предупреждением, а не причиной падения.

Полный сервер приложения рассчитан на постоянный процесс с локальной SQLite и Python/YOLO. У функций Vercel файловая система только для чтения, кроме временной `/tmp`. Поэтому одной смены версии Node.js недостаточно для размещения всей системы: нужны постоянное хранилище и отдельный сервер анализа. Перенос рабочей SQLite в `/tmp` не обеспечивает сохранность и общую синхронизацию.
