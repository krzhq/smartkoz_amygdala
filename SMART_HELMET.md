# SmartKóz — AI Smart Helmet

Модуль добавлен в существующие Express, SQLite, SSE и интерфейс SmartKóz. Нового приложения или независимой видеосессии руководителя нет.

## Модель

Файла `microdream.pt` в репозитории нет. По согласованию используется существующий **`microdream/dreameye.pt`**; веса не переименованы и не заменены. Модель загружена и проверена реальным инференсом.

Реальные классы:

```text
0 eyeLeftClose    1 eyeLeftOpen    2 eyeLeftSquint
3 eyeRightClose   4 eyeRightOpen   5 eyeRightSquint
6 microsleep     7 mouthClose     8 mouthOpen     9 neutral
```

Перед сменой по-прежнему используется отдельная модель СИЗ. Каска не меняет её работу. Для Smart Helmet требуется активная смена зарегистрированного сотрудника.

В обработчике сопоставлены фактические названия классов. Прищур — неопределённое состояние. Закрытие подтверждается двумя отдельными обнаруженными глазами с confidence ≥ 0.5 и закрытым состоянием; перекрывающиеся дубликаты удаляются class-agnostic NMS. Один закрытый глаз не запускает таймер. Один или два уверенно открытых глаза без противоречащих обнаружений могут подтверждать открытое состояние. Более двух глаз или противоречащие результаты не считаются нормой. Самостоятельный класс microsleep не используется как доказательство закрытия глаз или медицинского состояния.

## Запуск и телефон

**Камера ноутбука / Iriun без смены:** во вкладке «Каска» доступна кнопка «Включить камеру» и список «Источник камеры», в том числе руководителю. После разрешения браузера выберите встроенную камеру или Iriun Webcam. Переключение источника переподключает камеру. Без активной смены запускается локальная проверка с настоящей YOLO; фиктивные сотрудники и сессии не создаются, события смены не сохраняются. Для Iriun должен работать её клиент и камера должна быть доступна браузеру. После изменения backend перезапустите сервер, страницу обновите с Ctrl+F5.

Зависимости Node/Python уже установлены в рабочем каталоге. Повторная установка описана в README.

```powershell
npm start
```

На компьютере `http://localhost:3000` позволяет использовать камеру в защищённом контексте localhost. Для телефона обычный `http://192.168…` не подходит для `getUserMedia`: нужен HTTPS, которому доверяет браузер телефона.

### HTTPS в одной Wi-Fi сети

Сервер поддерживает TLS напрямую, без второго backend. Нужны сертификат и ключ для LAN IP компьютера, причём сертификату должен доверять телефон. Для локальной разработки можно использовать [mkcert и его инструкции для мобильных устройств](https://github.com/FiloSottile/mkcert#mobile-devices).

После самостоятельной установки mkcert пример для компьютера с IPv4 **192.168.1.25**:

```powershell
New-Item -ItemType Directory -Force data/tls
mkcert -install
mkcert -cert-file data/tls/smartkoz.pem -key-file data/tls/smartkoz-key.pem localhost 127.0.0.1 192.168.1.25
```

Замените пример IP своим адресом из `ipconfig`. Команда `mkcert -install` добавляет локальный центр сертификации в доверенные на компьютере; приложение само этого не делает. На телефоне нужно отдельно установить и разрешить доверие **публичному** `rootCA.pem` из каталога `mkcert -CAROOT`, согласно официальной инструкции и политике устройства. Приватный `rootCA-key.pem` передавать не нужно. Если устройство не разрешает локальные сертификаты, используйте доступный вам HTTPS-сервер с доверенным сертификатом; обход защищённого контекста в приложении не предусмотрен.

Добавьте в `.env`:

```dotenv
PORT=3000
TLS_CERT_FILE=data/tls/smartkoz.pem
TLS_KEY_FILE=data/tls/smartkoz-key.pem
```

Перезапустите `npm start`. Оба устройства открывают **`https://192.168.1.25:3000`**. Разрешите порт в Windows Firewall для частной сети при необходимости. `data/tls/` исключён из Git. При задании только сертификата или только ключа сервер откажется стартовать вместо незаметного перехода на HTTP.

HTTPS endpoint проверен временным тестовым сертификатом; системное доверие не изменялось. Установка сертификата на физический телефон в этой сессии не выполнялась.

### Рабочий сценарий

1. На ноутбуке войдите руководителем и откройте вкладку **«Каска»**.
2. На телефоне войдите зарегистрированным сотрудником, пройдите СИЗ и начните смену.
3. Откройте **«Каска»**, выберите фронтальную или основную камеру и нажмите **«Включить камеру»**. Разрешите доступ браузеру.
4. Закрепите телефон так, чтобы глаза одного человека были хорошо видны. Нужны свет, резкость и достаточный размер глаз в кадре.
5. На ноутбуке выберите сессию сотрудника. Это обработанные кадры **той же сессии**, а не камера ноутбука. ФИО, ID смены и ID сессии совпадают на устройствах.
6. В «Сотрудниках» колонка **Smart Helmet** обновляет состояние и время анализа через SSE.
7. Кнопка **«Остановить мониторинг»** завершает выбранную сессию. Если её нажал руководитель, телефон получает событие и освобождает камеру. Для смены фронтальной/основной камеры остановите мониторинг и запустите нужную камеру.

При обновлении исходной вкладки её producer token сохраняется в sessionStorage: камера может продолжить ту же серверную сессию. Другая вкладка не получает права отправлять кадры автоматически. Если исходная вкладка недоступна, сотрудник или руководитель может явно завершить старую сессию и начать новую. Новая сессия не создаётся автоматически на каждом устройстве.

## Проверка предупреждений

Демонстрацию проводите в безопасной обстановке, вне работы с оборудованием.

- Убедитесь, что есть реальные рамки глаз. Статус «Норма» появляется только после минимум трёх последовательных открытых наблюдений за интервал не менее 0.5 секунды.
- Короткое закрытие примерно на секунду показывает «Глаза закрыты», но не создаёт предупреждение.
- При уверенной последовательности закрытия двух глаз не менее 3 секунд появляется **EYES_CLOSED_WARNING**. Уведомление с ФИО поступает руководителю; одно непрерывное событие не дублируется на каждом кадре.
- Устойчивое открытие глаз завершает событие и сохраняет время окончания и длительность.
- После устойчивого обнаружения глаз направьте камеру в сторону так, чтобы глаз не было видно. После 2 секунд успешно обработанных кадров без глаз появится **VISIBILITY_LOST** — возможное снятие каски или потеря видимости, не доказанное снятие.
- Верните глаза в кадр. Видимость восстанавливается после нескольких достоверных наблюдений. Предупреждение о закрытых глазах отдельно требует устойчивого открытого состояния.
- Отключение камеры или прекращение передачи захвата более 6 секунд создаёт **CAMERA_DISCONNECTED**, а ошибка модели — **AI_UNAVAILABLE**. Потеря связи с backend отдельно показана на клиенте: старый кадр скрывается и «Норма» не остаётся на экране.

Если рамки не появляются, не выдавайте это за норму: проверьте положение камеры, освещение, размер глаз и статус модели. Слабые/противоречащие обнаружения не подтверждают нормальное состояние.

## Поток и хранение

- Браузер использует `getUserMedia()`, локальный предпросмотр и JPEG-кадры размером до 640 px по длинной стороне. Звук не захватывается.
- Один Python-процесс держит YOLO в памяти. Повторной загрузки весов на каждом кадре нет. Используется существующая сериализация рамок из `scripts/analyze_yolo_video.py`.
- Не более 4 запросов анализа в секунду на сессию; клиент ждёт результат перед отправкой следующего свежего кадра. Общей очереди кадров нет: занятый worker отвечает 429. Реальный FPS зависит от CPU и числа сессий, отображается в интерфейсе.
- Большой экран показывает обработанный JPEG и рамки именно этого кадра. Локальное видео показано отдельно, поэтому рамки не накладываются на более новый неподходящий кадр.
- Выключение bounding boxes меняет только визуализацию и не останавливает анализ.
- Один producer token привязан к одной активной сессии сотрудника и смене. В SQLite хранится только хеш token; токен не выдаётся зрителям. ADMIN смотрит сессию, но не подменяет её кадры.
- Таймеры используют серверный `performance.now()`, а не число кадров или часы телефона. Короткий пропуск допускается до 0.8 секунды; длительная неопределённость или интервал между результатами более 1.5 секунды прерывают накопление доказательств.
- При перезапуске история остаётся, но старый NORMAL и временные интервалы не восстанавливаются. Сессия помечается потерявшей камеру и ожидает свежего подключения. Запоздалый результат отключённого потока не может вернуть NORMAL.
- Последний JPEG хранится только в RAM, очищается при остановке/потере камеры. Изображения и видео каски на диск не записываются. В SQLite сохраняются события и последняя метаинформация анализа с координатами.
- Завершение смены останавливает связанную сессию серверным watchdog. Окончание события при остановке записывается с причиной остановки; оно не выдаётся за восстановление зрения.
- «Ознакомлен» в истории фиксирует действие руководителя, но не закрывает активное предупреждение.

## SQLite и API

`helmet_sessions` связана с существующими `employees` и `shifts`: начало/окончание, состояние камеры, последнее поступление/анализ, последовательность кадров, хеш producer token и последний результат. Уникальные индексы допускают одну активную сессию на сотрудника/смену.

`helmet_events`: session_id, employee_id, тип, критичность, начало фактического эпизода, время срабатывания порога, окончание, duration_seconds, confidence, подтверждение ознакомления руководителем и причина завершения. Один незавершённый event данного типа на сессию. Используются существующие `notifications`, `audit_logs` и SSE.

| API | Доступ |
| --- | --- |
| `GET /api/helmet` | ADMIN: сессии/события; EMPLOYEE: только свои |
| `POST /api/helmet/sessions` | EMPLOYEE на активной смене |
| `POST /api/helmet/sessions/:id/resume` | Владелец с producer token |
| `POST /api/helmet/sessions/:id/frames` | Владелец с producer token; только JPEG, sequence и token |
| `GET /api/helmet/sessions/:id/frame` | Владелец или ADMIN; согласованные кадр и метаданные |
| `POST /api/helmet/sessions/:id/heartbeat` | Producer, сигнал работающего захвата |
| `POST /api/helmet/sessions/:id/disconnect` | Producer, отдельное событие потери камеры |
| `POST /api/helmet/sessions/:id/stop` | Владелец или ADMIN |
| `POST /api/helmet/model/retry` | Авторизованный повторный запуск модели |
| `POST /api/helmet/events/:id/acknowledge` | ADMIN; ознакомление, не снятие предупреждения |

## Тесты и пределы

```powershell
npm test
npm run build
npm run test:helmet:ai
npm run test:helmet:browser
npm run test:browser
```

Временные базы и тестовые пользователи не попадают в рабочую SQLite. Для проверки таймеров unit-тесты используют искусственные последовательности результатов; рабочий API не принимает готовые результаты и не имеет режима имитации. Реальный AI-тест обрабатывает кадры исходного видео `microdream/microsleepdriver.mp4`. Browser-тест использует тестовое устройство захвата Chromium и настоящий YOLO; это проверка браузерного пути, а не утверждение об испытании физической каски или телефона. Подробные результаты — в VERIFICATION.md.

Ограничения: один CPU-worker, передача отдельных обработанных кадров, задержка сети и пропуск кадров при нагрузке; нет фоновой камеры при закрытом/приостановленном браузере и Web Push. Нельзя гарантировать обнаружение при плохом освещении, малых размерах глаз, очках, перекрытии или ошибке модели. Если анализ слишком медленный, доказательства непрерывности не накапливаются и NORMAL не заявляется. Класс отсутствия глаз не доказывает снятие каски, а закрытие глаз не является диагнозом. Это демонстрационный прототип для последующих аппаратных и промышленных испытаний.
